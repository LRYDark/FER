Pour en faire un PDF : ouvrez ce fichier dans un navigateur, puis Ctrl+P (ou ⌘+P sur Mac) → Destination : Enregistrer au format PDF.

Installer et tester les applications

Forbach en Rose — guide complet, en partant de zéro. Partie A : le Mac (iPhone, iPad, Apple Watch). Partie B : Windows (Android, Wear OS).

Par quoi commencer ? Par Android, même si votre cible est l'iPhone. Plus de 90 % du code est commun, et la boucle « modifier / relancer » y est bien plus rapide. Ce qui fonctionne sur Android fonctionnera sur iOS, à la signature près.

Ce qu'il faut avoir sous la main

  • Le dossier APPS du projet
  • Mac : identifiant Apple, et le compte Apple Developer (99 €/an) pour tester sur un vrai iPhone
  • Android : un téléphone avec le débogage USB activé, et son câble
  • Une bonne connexion — les téléchargements pèsent plusieurs gigaoctets

Partie A — Le Mac

Votre Mac n'a ni brew ni flutter. On part donc vraiment de zéro. Comptez 1 h 30 à 2 h, dont l'essentiel en téléchargement.

1Xcode 30 à 60 min

Ouvrez l'App Store → cherchez Xcode → Obtenir. C'est gros (~15 Go). Lancez-le maintenant et faites la suite pendant qu'il télécharge.

Une fois installé, ouvrez Xcode une première fois : il installe des composants supplémentaires et demande d'accepter la licence. Puis, dans le Terminal :

sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
⚠ Ne sautez pas l'ouverture d'Xcode. Sans elle, les commandes ci-dessus échouent avec un message qui ne parle pas de licence, et on cherche longtemps.

2Homebrew 10 min

C'est le brew: command not found que vous avez rencontré : Homebrew n'est pas fourni avec macOS, il faut l'installer.

Ouvrez le Terminal (⌘+Espace → « Terminal ») et collez :

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Il demande votre mot de passe de session (rien ne s'affiche pendant la frappe, c'est normal), puis travaille quelques minutes.

⚠ LE PIÈGE : à la fin, brew reste introuvable. Sur les Mac Apple Silicon (M1, M2, M3, M4), Homebrew s'installe dans /opt/homebrew, qui n'est pas dans le PATH. Le script vous l'écrit dans ses dernières lignes — mais on ne les lit jamais. Exécutez : 
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

Sur un Mac Intel, remplacez /opt/homebrew par /usr/local.

Vérifiez :

brew --version
✓ Attendu : Homebrew 4.x.x. Si c'est encore « command not found », fermez le Terminal et rouvrez-le.

3Flutter et CocoaPods 15 min

brew install --cask flutter
sudo gem install cocoapods
Sans Homebrew ? C'est possible : téléchargez l'archive sur flutter.dev/docs/get-started/install/macos, dézippez-la dans votre dossier personnel, puis ajoutez-la au PATH : 
echo 'export PATH="$HOME/flutter/bin:$PATH"' >> ~/.zprofile
source ~/.zprofile

Le contrôle général :

flutter doctor
✓ Attendu : Xcode et CocoaPods en vert. « Android toolchain » et « Chrome » peuvent rester rouges — vous ne compilez pas Android sur ce Mac.

4Copier le projet — deux dossiers 5 min

⚠ C'est LE piège du transfert. Il faut mac/ et bibliotheque/, côte à côte : 
QuelqueDossier/
├── mac/
└── bibliotheque/

mac/pubspec.yaml déclare path: ../bibliotheque/fer_shared. Sans le voisin, flutter pub get s'arrête sur « path does not exist ».

Clé USB, AirDrop, scp, dépôt git : peu importe, tant que les deux voyagent ensemble.

5Générer le projet iOS 5 min

cd ~/QuelqueDossier/mac
flutter create --platforms=ios --org fr.forbachenrose --project-name fer_ios .
flutter pub get
⚠ flutter create conserve lib/ et pubspec.yaml. S'il propose de les écraser, arrêtez tout : vous n'êtes pas dans le bon dossier.

6Fusionner l'Info.plist 5 min

Ouvrez ios/Runner/Info.plist et ajoutez les clés du fichier ios-overlay/Info-additions.plist — chacune y est expliquée.

⚠ N'écrasez pas le fichier. Vous perdriez le nom du bundle, les orientations et l'écran de lancement générés par Flutter.

Ces clés sont les textes qu'iOS montre à la personne quand l'application demande sa position ou le Bluetooth. Apple les lit à chaque soumission : une phrase vague est un motif de rejet documenté.

7Signer dans Xcode 10 min

open ios/Runner.xcworkspace
⚠ .xcworkspace, jamais .xcodeproj. Avec le second, les greffons CocoaPods ne sont pas liés et la compilation échoue sur des symboles introuvables — un message qui ne dit jamais « vous avez ouvert le mauvais fichier ».

Dans Xcode, sélectionnez la cible Runner :

  • Onglet Signing & Capabilities
  • Cocher Automatically manage signing
  • Choisir votre Team (votre compte Apple Developer)
  • Bundle Identifier : fr.forbachenrose.coureur
  • + Capability → Background Modes → cocher Location updates et Uses Bluetooth LE accessories
  • + Capability → Push Notifications

8Lancer 5 min

flutter devices     # liste ce qui est disponible
flutter run         # lance sur l'appareil trouvé

Ensuite : la montre et le chrono vivant

L'Apple Watch et la Live Activity sont deux cibles Xcode supplémentaires, en SwiftUI. Gardez-les pour un second temps, quand l'iPhone tournera. Voir README/03-apple-watch.md et README/07-chrono-vivant.md.

Partie B — Windows et Android

Comptez 1 h. C'est ici qu'il faut développer au quotidien : la boucle est bien plus rapide que sur Mac.

1Android Studio 30 min

Téléchargez sur developer.android.com/studio, installez, puis lancez-le une fois : il télécharge le SDK Android. Acceptez tout ce qu'il propose.

2Flutter 15 min

Le plus simple passe par VS Code, où l'extension Flutter est déjà installée :

  • Ctrl+Maj+P → Flutter: New Project
  • VS Code répond « Flutter SDK not found » → cliquez Download SDK
  • Choisissez un dossier sans espace ni accent : C:\flutter convient
⚠ Le chemin compte vraiment. Un dossier comme C:\Users\joris.reinert\Mes documents\flutter casse la compilation Android, avec des messages qui ne parlent jamais du chemin.

Puis, dans un terminal :

flutter doctor
flutter doctor --android-licenses
✓ Attendu : tout en vert sauf « Xcode » — normal sous Windows.

3Générer le projet Android 5 min

cd W:\FER\APPS\android
flutter create --platforms=android --org fr.forbachenrose --project-name fer_android .
flutter pub get

4Fusionner le manifeste 10 min

Ouvrez android/app/src/main/AndroidManifest.xml et ajoutez ce que contient android-overlay/AndroidManifest.xml — chaque permission y est expliquée.

  • Les blocs <uses-permission> et <uses-feature>, avant <application>
  • Le <receiver> de redémarrage, dans <application>
  • android:launchMode="singleTop" sur <activity android:name=".MainActivity">
⚠ Deux lignes à ne pas manquer. SCHEDULE_EXACT_ALARM : sans elle, Android peut décaler le rappel de plusieurs dizaines de minutes — pour « départ dans 2 h », il arrive après le départ. Et n'ajoutez jamais ACCESS_BACKGROUND_LOCATION : elle permettrait de suivre quelqu'un application fermée, et Google exige une justification vidéo.

Enfin, dans android/app/build.gradle.kts :

defaultConfig {
    minSdk = 26          // Android 8.0
    targetSdk = 34
}

minSdk = 26 et pas moins : en dessous, le Bluetooth ne fonctionne pas, et il ne reste plus qu'une source de chronométrage au lieu de deux.

5Lancer 5 min

Sur le téléphone : Paramètres → À propos → toucher 7 fois « Numéro de build », puis Options pour développeurs → Débogage USB. Branchez-le et acceptez la demande d'autorisation qui s'affiche.

flutter devices                            # le téléphone doit apparaître
flutter run                                # téléphone et tablette
flutter run -t lib/main_montre.dart        # Wear OS
Deux points d'entrée, un seul projet. Le téléphone démarre sur lib/main.dart, la montre sur lib/main_montre.dart. Même dossier, même cœur — seuls les écrans changent.

6Ce qu'il faut essayer 20 min

  • Connexion : saisir son adresse, recevoir le code à 6 chiffres, entrer
  • Mes inscriptions : la liste s'affiche, le QR code se charge
  • Sans réseau : mode avion → déclarer un passage → réactiver → vérifier que la file part
  • Le rappel : régler l'heure de départ à ~10 min, fermer l'application, attendre
  • Le chrono : démarrer le suivi, éteindre l'écran, vérifier que la notification compte toujours
⚠ Le test « sans réseau » est le plus important. C'est la situation réelle du jour de la course : trois mille personnes sur la même antenne, un téléphone au fond d'une poche. Si la file ne repart pas, quelqu'un franchit la ligne sans chrono.

Avant tout essai : le serveur
